# 拍照辨識台數 — 開發紀錄

用相機拍麻將牌，自動辨識手牌並計算台數/胡牌種類。這份文件記錄設計討論、決策與待辦，依時間順序新增條目。

---

## 2026-08-09

### 目標
拍照 → 辨識這手牌是哪 13/14 張 → 結構化資料顯示給玩家確認 → 確認無誤後才餵給台數計算規則引擎算台。

### 決策
- **辨識與計分分離**：拍照辨識只負責「認牌」，不直接自動送出分數。辨識結果要先給玩家看一眼、可手動修正，才會寫入歷史紀錄（比照現有記錄局數的預覽/確認流程）。
- **不做純雲端 API 方案**：目前專案定位是「純前端單檔案、無外部依賴、可離線使用」，若辨識依賴雲端 Vision API 會違背這個定位，先不採用。
- **台數規則表獨立於辨識進度**：具體台數規則（門清、碰碰胡、混一色、清一色、字一色…）要先整理成規則表，這部分不受辨識模型進度影響，可以並行/優先進行。

### 待決定
- 辨識模型放哪裡跑：
  - 前端 TensorFlow.js（維持離線特性，但模型要自己找/訓練，手機推論可能較慢）
  - iOS 原生 CoreML（利用現有 `ios/` WKWebView 外殼，僅 iOS 版可用，網頁版需要退化方案）
- 訓練資料從哪裡來（現成麻將牌偵測資料集 vs. 自己標註）
- 網頁版在沒有原生辨識能力時的 fallback（維持手動輸入，或降級用較陽春的前端模型）

## 2026-08-09（續）

以標準台灣 16 張麻將公定台數表為基礎，整理出第一版台數規則草案（[TAI_RULES.md](./TAI_RULES.md)），涵蓋基本台、花牌、牌型組合台、特殊胡牌時機。表格明確標記為草案，還有幾項需要跟實際玩法核對後才能定案（花牌正花對應、天胡/地胡等是否封頂滿貫、連莊是否加台、聽牌型態是否計台），詳見文件內「尚待確認事項」。

## 2026-08-09（拍照擷取 UI）

先做「拍照」本身的擷取功能，辨識模型還沒接上去。

### 完成項目
- 「記錄本局」modal 最上方新增「拍照輔助（Beta）」區塊：`<input type="file" accept="image/*" capture="environment">` 觸發相機/相簿，選好照片後在 modal 內顯示縮圖預覽，並標註「自動辨識台數開發中，請依照片手動選擇下方項目」，同時提供「移除照片」按鈕。
- 照片只存在 `G.modal.photo`（記憶體內的 base64 data URL），modal 關閉/重新開啟時會被清空，**不會**寫入 `localStorage` 或歷史紀錄，避免瀏覽器儲存空間爆量。
- iOS 專案（`ios/project.yml`）加上 `NSCameraUsageDescription`，並重跑 `xcodegen generate`，否則 WKWebView 觸發相機時會直接 crash。

### 決策
- 這一版純粹是「拍照 + 預覽」的骨架，刻意不把照片存進 `round` 紀錄，因為還沒決定要不要拿使用者拍的照片來累積訓練資料集（見下方待確認）。等辨識模型方向確定後，再回頭決定要不要把照片持久化、存哪裡。
